# 协作与审查安排

任务范围与顺序见[当前计划](current.md)，状态见[统一台账](ledgers/roadmap.csv)。实际分派时先确认共同源码起点和修改归属。

| 工作线 | 可独立准备的专题 | 共享依赖 |
| --- | --- | --- |
| 原生适配 | D001、D002、D003 | 公共注册/能力元数据统一集成 |
| 几何与追迹 | D004、D009 | 变换与几何参考复用 |
| 传播 | D005、D011 | POP/PSF坐标和归一化 |
| 评价与优化 | D006、D007、D008 | 原生优化入口与候选调度 |
| 路径与环境 | D010、D012 | 路径功率归属、热配置 |

共享入口包括`models.py/server.py/backend.py/analysis_models.py`，各工作线列明最小补丁，由集成负责人依次合入。专题逻辑和数值参考可在独立模块实现。每个工作区显式记录实际源码导入位置，避免共享虚拟环境读到其他分支。

原生测试、直接API、真实stdio及任何创建OpticStudio实例的操作统一串行。排队信息包含条目、命令、输入、解释器、输出目录、预算和终态；前一作业关闭后运行下一项。

每项先交实施计划，再交实现/定向普通检查，最后交原生证据及状态建议。审查内容依据[计划第7节](plan.md#7-完成状态与证据)。后续需要worker时优先复用现有可用worker，接新任务前传入本计划与当前源码起点。

本次计划整理未启动worker或监督循环。具体并行数量和职责以实际分派记录为准。
