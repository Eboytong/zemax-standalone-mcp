## 1. 目标与依据

让Agent自主选择原生能力、目标和执行顺序，降低首次工具披露和重复契约的上下文开销。保留已验证的任务、恢复、候选和数值聚合，工程流程按需使用。优先修正已观察到的重复schema和无关前置条件。

[调研报告](tool-disclosure-research.md)记录源码审查与一手资料；[测量证据](evidence/PLAN-20261111-DISCLOSURE/README.md)记录真实stdio结果。107个工具描述紧凑序列化为1,431,740字节；7个大接口的输入占全部输入schema的88.4183%。宿主实际注入的定义、模型token和任务完成率在D023/D027测量。

已发行D017—D022的6/6终态保存在[归档](archive/engineering-search-20261111/README.md)。原有功能和验收证据继续有效，本期完成数仅计算D023—D027。

## 2. 架构与取舍

| 层次 | 职责 | 本期处理 |
| --- | --- | --- |
| Agent/宿主 | 目标、方法、调用顺序、停止策略、可选子Agent | 实测原生发现，提供可组合调用例子 |
| 能力披露 | 短索引、准确契约、单位、条件、结果定位 | 按工具/kind/action披露，增加compact模式 |
| 原生动作 | 建模、MFE、光线、分析、优化、公差、文件 | 沿用有类型请求和实际设置回读 |
| 确定性服务 | 任务、副本/恢复、候选和数值聚合 | 复用现有执行所有者与结果链 |
| 可选工程流程 | 联合玻璃、目标模板、制造良率路线 | 解除无关绑定，展示实际算法和底层入口 |

full保留现有107工具。compact候选为9个现有引导/控制工具，加`query_capability`和`execute_capability`两个固定入口，共11个。模式共用调用适配来源、Bridge和原生执行机制；用户选择一个连接。

流程：检索 → 单能力精确契约 → 有类型校验后调用 → 现有状态/结果/分页/取消。已知能力ID可直接使用，检索负责提供候选。MCP规范对工具目录稳定性的要求见调研S3；模式在进程启动时固定，能力搜索返回资料。

子Agent工具选择作为宿主层条件实验，优先用于模糊跨领域任务和大量资料阅读。MCP服务器保持确定性执行；原生对象仍由一个所有者串行操作。

## 4. 逐项任务书

### D023：宿主与工具上下文基线

1. 固定1.3.0源码、导入路径、Python、MCP SDK和客户端版本。复用测量程序，分别统计107工具的input/output/说明及嵌套联合。
2. 核实本机Codex的目录获取、缓存、原生工具检索、单工具加载粒度、白名单和重连行为；保留正式配置或日志支持的观测。Responses工具搜索按其独立API机制验证。
3. 分列传输字节、实际提供给模型的定义、结果字节、usage/token和缓存命中。不可观测的字段标明实际来源与替代指标；相同口径比较。
4. 冻结60条任务：校核扩展30条既有检索题，另30条覆盖稀有能力、同义词、跨域多步、参数约束和未知能力。标注可接受工具集合、成功输出及副作用。
5. 选12条端到端用例，覆盖顺序、NSC、POP、优化、公差和逐面损耗。先运行6条小试，固定采集命令、模型版本、输入、预算与判定器，再正式对照。

**文件。** 产品源码只读；任务集与采集记录放`development/evidence/D023/`，原始内容放`.local/evidence/`。API对照使用已有运行条件。

**完成门槛。** 真实stdio目录与关闭记录、客户端事实表、60条任务和12条端到端子集齐全；记录宿主原生发现已解决的内容与分析级大联合的剩余开销。

### D024：精确schema与轻量目录

1. 从原有请求模型生成能力目录，标注原生动作、确定性服务和可选工程流程。短列表只返回ID、用途、影响和详情入口。
2. 单kind详情只返回该分支及可达定义；处理`$ref`、discriminator映射、数组/组合/递归引用，保留枚举、默认值、范围和互斥条件。
3. 对`manage_candidates`等action联合提供分支详情。复合评价可指定本次使用的analysis kinds，返回相应嵌套契约；完整schema仍可显式读取。
4. 单次详情与原始Pydantic模型共用来源，后台仍校验完整合法请求。搜索、示例、依赖和长说明分层返回，保持稳定排序。
5. 107工具和146分析均可直接ID定位。完整联合中实际引用的类型继续保留。

**文件。** `capability_index.py`、schema辅助模块、能力请求字段、相关普通测试和例子。

**检查。** 全量kind/action可定位、没有悬空引用；覆盖多层、递归、重名定义。用合法/非法请求核对所选契约与原模型；检查离线搜索及stdio失败后复用。

**完成门槛。** wavefront详情≤2,000字节；详情只含所需定义；冻结任务Top-5召回≥57/60。正式工具schema的有效分支保持原义。

### D025：稳定compact发现及执行

**候选合同。** `query_capability(capability_id, arguments)`接受确认的只读操作；`execute_capability(capability_id, arguments)`处理其余操作。外层为小型JSON对象，内层按原请求模型校验。

1. 提取MCP函数调用适配表，记录工具层参数、内部command、包装及`exclude_unset`；复用同一处理函数链，验证全部107工具。
2. 注册能力ID指向工具、kind或action。仅调用注册能力；参数错误沿用原有字段路径和修正信息。
3. 审查annotations与实际模型/文件影响，query仅开放确认的读取。未知影响进入execute；宿主保留两类入口的不同权限配置。
4. 增加启动配置`full/compact`，注册表在启动时固定。9个常驻工具为`connect`、`disconnect`、`get_status`、`search_capabilities`、`get_capabilities`、`get_task_status`、`get_task_result`、`cancel_task`、`get_request_status`。
5. 两个执行入口沿用Bridge/Backend，保持请求ID、任务ID、busy、超时查询、取消、局部修改、恢复和关闭。适配直接进入现有处理链，避免二次包裹dispatch改变响应与修订语义。
6. 结果先给摘要与句柄；光线、网格和样本继续通过现有分页或文件取得，明确总量、返回范围和下一页。
7. 安装/启动脚本提供模式选项，显式配置优先。full调用继续兼容。

**文件。** `server.py`、统一调用适配/注册、必要模型和启动配置；用户指南在功能实现后更新。

**检查。** 107工具映射、146kind路由、显式默认/省略字段、只读入口拒绝写操作、未知能力、busy、超时状态及取消。真实stdio分别在full/compact完成建模、光线或MTF、分页、图像和断开；原生串行。

**完成门槛。** compact启动目录≤20,000字节；全部能力可达；设置与结果沿用full合同和已有数值容差。默认模式由D027决定。

### D026：工程流程解耦与自主组合

1. `glass_trials`增加有类型贡献选项，默认沿用原行为。关闭贡献时，槽位与试验检查目录、材料段、solve和相应原生评价条件。
2. Standard、同轴、无穷远、三波长和Y场等条件仅作用于贡献计算。按实际系统选择评价指标，保留具体不可用原因和原始错误。
3. 提供显式联合赋值、既有预算搜索、Agent逐候选调用三种例子；同基线、同评价合同、同预算比较，记录实际赋值和副本关闭。
4. 评价函数保留预览/应用模板与直接MFE入口；去敏感化准确呈现制造良率向导、DLS、分布、变量和采样。检索同时指出可组合的原生MFE、优化和公差入口。
5. 提供Agent自选目标/变量/优化器→原生执行→评价→候选保存的例子。其他优化策略使用现有Global/Hammer等正式工具，任务和恢复复用原机制。

**文件。** `glass_trials.py`、`joint_glass.py`、相关模型、元数据和例子；候选、merit、去敏感化按本项实际需要调整。

**检查。** 贡献开关、默认兼容、参数与失败恢复；至少一个原贡献模型及一个关闭贡献后可运行的受控非球面或有限共轭模型。显式组合与逐项原生调用同预算比较，采用既有容差；检查材料回读、恢复、保存/重载和关闭。

**完成条件。** 原生材料试验独立于贡献分析运行；Agent可用底层入口完成相同目标；工程流程保持可选且可复现。

### D027：模式对照、默认选型及统一发行

1. 用D023冻结任务比较A当前full、B宿主原生发现、C compact。记录每模式实际支持和加载路径；模型/输入/预算/判定器固定，冷启动与复用分列。
2. 12条端到端用例从独立基线串行运行，交替对照顺序，采用既有光学数值、模型状态和生命周期要求。
3. 条件子Agent实验优先8条模糊/跨域题。子Agent只选能力、查资料和提出步骤，主调用链执行原生操作；记录父子总token、延迟和成功输出。宿主条件不足时交付实际探查与后续动作。
4. compact建议门槛：完成数至少达到full、启动≤20,000字节、Top-5召回≥57/60；token可观测时，总token中位数降低≥50%，P95延迟增加≤20%。未满足的模式按具体任务结果保留为可选配置。
5. 子Agent进入推荐配置的门槛：模糊子集新增至少2条成功，或成功数相同时父子总token中位数降低≥20%。每次路由实际收益单独报告。
6. 执行一次阶段集中普通回归，串行运行注册/派发、任务和玻璃试验的受影响原生回归。构建1.4.0，独立安装验证两模式、真实stdio、结果/分页/导出及正常关闭。
7. 更新能力、schema、示例、安装说明、发行记录、台账与交接。D023—D027全部完成后统一发行。

**完成条件。** 对照数据可重跑；默认模式选择有完成率与成本依据；full兼容和发行检查通过；交付实际安装包。条件子Agent结果单列。
